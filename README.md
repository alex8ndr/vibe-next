## About

Vibe is a full-stack music recommendation app that helps you discover artists and tracks similar to what you already like.

As someone who listens to a lot of music, I am always looking to discover new artists.
While platforms like Spotify and YouTube Music already have recommendation algorithms, I wanted something that felt more intentional. Something similar to the experience of walking through a bookstore and picking out books, but for music, without the hidden workings and biases of existing recommendation algorithms.

The website is designed to make it easy to discover new artists while streamlining the discovery and listening process. Before creating Vibe, I tried other music recommendation websites and found they usually fell into two types. Some recommended artists similar to ones I already knew, but did not recommend any songs from them, so I still had to do the work to find and listen to them myself. Others recommended specific songs, but without enough artist context. I wanted one flow where I could get multiple song recommendations for multiple artists and listen to those songs all from the same page.

## Features

- Select 1–5 input artists, optionally with up to 5 seed songs each
- Recommendations returned as songs grouped under recommended artists
- Integrated Spotify embeds for in-page playback
- Regeneration, favorites/known-artist management, and export utilities
- Runtime controls: `diversity`, `genre_weight`, `tracks_per_artist`, `max_artists`

## How it works

Recommendations are generated by combining audio feature distance, genre profile distance, and language match. For multi-seed queries, the ranking uses a soft-min style aggregation so strong matches can still influence results without ignoring the rest of the input profile.

## Repo structure

- `frontend/` Svelte app and UI logic
- `backend/app/` API + recommendation runtime
- `backend/scripts/` pipeline and discovery tooling (see [scripts README](backend/scripts/README.md))
- `backend/data/` serving artifacts, manifest metadata, and external datasets
- `backend/data/external/` raw and preprocessed source datasets
- `backend/data/external/genre/` artist genre parquets (precedence: yamac > malte > vectorql > serkan > musicbrainz > discogs)
- `legacy/` older reference implementation

## Data setup

The app requires track and artist data in parquet format. Data is not included in the repo.

The pipeline accepts any track dataset in parquet or CSV format — drop files into `backend/data/external/` and run the pipeline. For preprocessing raw CSVs, column mapping is auto-inferred. See [`backend/scripts/README.md`](backend/scripts/README.md) for full setup, preprocessing, and pipeline instructions.

## Run locally

### 1) Backend

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Backend expects:
- `backend/data/tracks.parquet`
- `backend/data/artists.parquet`

### 2) Frontend

```bash
cd frontend
pnpm install
pnpm dev
```

By default, frontend uses local backend on port 8000.
